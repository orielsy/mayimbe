# Stage 1 — Mayimbe notebook static asset system

A new standalone inspection page at `/labs/notebook-assets`, fed entirely by pre-exported image files. No page-turn, no cover opening, no canvas, no WebGL, no Three.js on this route. Every existing notebook route stays untouched.

## Where the artwork comes from

The project already owns the winning artwork: the brick F3-03 cover, the paper stock/fibre/foxing/crease/stain/grime/humidity/drift language, and the M2 irregular edge profiles. Rather than invent new looks, an offline baker runs those exact drawing functions once and writes flat image files. Reloading the page never redraws anything.

The baker extends the existing offline tool pattern (`extraction/notebook-native/tools/bake-surfaces.mjs`) into a new sibling script that outputs a Stage 1 library under `public/notebook-assets/`. Fixed seeds mean repeated runs produce byte-identical artwork.

## The asset library (840 × 1120 master, 3:4)

Substrates (opaque WebP):
- `substrate-carried`, `substrate-humidity`, `substrate-protected` — base paper tone + drift + fibre baked in, one per family

Reusable wear overlays (transparent WebP, independently positionable/mirrorable/fadeable):
- `fibre-stock` (tileable), `foxing-light`, `foxing-heavy`
- `water-stain`, `humidity-bloom` (tide marks)
- `grime-handling`, `edge-oxidation`, `tonal-drift`
- `smudge-abrasion`, `crease`

Edge silhouettes (transparent alpha masks): `edge-mask-a/b/c`, cut from three M2 fore-edge profiles.

Cover materials: `cover-brick-front` (approved F3-03 board, no title baked in) and `cover-brick-inside` (quieter pastedown version).

All wear files also get a small preview-safe size where useful; page consumption uses the master.

## Manifest

`public/notebook-assets/manifest.json`, generated by the baker:

```text
assets: [ { id, label, path, group, w, h, format, transparent } ]
recipes: {
  carried   : { substrate, edgeMask, layers: [ {assetId, opacity, blend, mirror} ... ] }
  humidity  : { ... }
  protected : { ... }
}
```
Recipes are ordered layer lists — the page renders a family by stacking its `layers` over its `substrate` inside its `edgeMask`. The intensity slider scales every layer's opacity together; toggles drop individual layers. Nothing about a family is hardcoded in the page.

## The page

Route file `src/routes/labs.notebook-assets.tsx` (`/labs/notebook-assets`), mobile-first at 390 × 844, clean at 1440 × 900, with its own head metadata. Museum-adjacent presentation: dark neutral ground, restrained serif headings, generous space, labelled specimen cards.

Sections:
1. **Overview** — "Notebook rebuild · Stage 1", exported asset count, master dimensions, "CSS + images", "Canvas 0 / WebGL 0".
2. **Composition workbench** — one convincing pocket page with a subtle static stack behind it; sample text stays live selectable DOM; family switcher; per-layer checkboxes; wear-intensity slider; a live list of the exact filenames currently composited.
3. **Recipe comparison** — the three families side by side (stacked on mobile) with each one's layer list.
4. **Cover assembly** — front board, inside board, and an assembled notebook with a static paper block; title stays live DOM text over the cover.
5. **Asset inventory** — every asset as its own card over a checkerboard, with filename, dimensions, format, role, and transparency; masks shown against contrast so their silhouette reads.

Semantic `<button>`/`<input>` controls with visible focus rings, `prefers-reduced-motion` respected, no horizontal overflow at either width.

## Verification before reporting

Load the route and confirm: no console errors, every `<img>` `complete && naturalWidth>0`, `document.querySelectorAll('canvas').length === 0`, no WebGL context, toggles and family switching visibly change the composition and the filename list, text selectable, identical after refresh, and both viewport sizes screenshot clean.

## Technical notes

- Baker: new `extraction/notebook-native/tools/bake-assets.mjs`, headless-browser rendering of the existing `paper-surface` / `cover-f3` / `paper-stack` code, WebP output, deterministic seeds. It is a build-time script only; nothing imports it at runtime.
- The page imports only the manifest JSON and plain `<img>`/CSS backgrounds — no `three`, no procedural modules.
- Existing routes, `public/notebook*`, `public/shared/*` and `public/notebook-textures/` are read for artwork but not modified.
